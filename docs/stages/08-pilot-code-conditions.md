# Этап 08 — условия пилота на стороне кода

Цель: снять с пилота то, что можно решить кодом, чтобы у оператора остались только шаги инфраструктуры и договорённости.
Критерий готовности этапа:
1. веб-бандл раздаётся настоящим статическим хостом из репозитория: `/book/<slug>`, `/b/<id>?token=`, `/clients/<id>`, `/specialists/<id>` открываются, неизвестный URL даёт 404 с `+not-found` (TD-57);
2. владелец анонимизирует клиента по запросу на удаление из консоли; персональные данные клиента не остаются в CRM, визитах, данных AI, аудите; обезличенные факты визитов и метрики прошлых периодов сохраняются (TD-46, `docs/PRODUCT_PLAN.md` §10);
3. перенос из консоли не упирается в публичный лимит по IP (TD-76);
4. на `/book` ошибка загрузки слотов, в том числе 429, отличается от «нет слотов» и даёт повтор (TD-55);
5. панель визита показывает снапшот цены владельцу, мастеру нет (TD-71);
6. хотя бы один проход записи каталога идёт через настоящий токен Keycloak (сейчас E10 только в dev-headers);
7. регрессия зелёная: backend и фронтенд как в CI, `npm run e2e`, `npm run e2e:oidc`.

Риск: HIGH для анонимизации (необратимо, персональные данные), MEDIUM для остального.

Не входит: фаза 4 (нужны решения по каналу и результаты пилота), TLS и DNS, офсайт-бэкап, DPA, живая проверка DeepSeek.

## Решения координатора
- Анонимизация только у OWNER, необратима, с явным подтверждением на экране. Клиента с будущими активными визитами анонимизировать нельзя: 409, сначала отменить их.
- Копии в бэкапах удаляются по сроку хранения, это остаётся в уведомлении о приватности.
- Статический хост — nginx из отдельного контейнера `web` в `docker-compose.prod.yml`, привязанного к loopback для внешнего прокси, как `app` и `keycloak`. TLS по-прежнему снаружи.
