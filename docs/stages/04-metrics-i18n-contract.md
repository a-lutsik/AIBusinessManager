# Этап 04 — метрики по журналу событий, локализация, контракт API

Цель: закрыть P1-пробелы ревью, которые можно доказать тестами без внешних провайдеров.
Критерий готовности этапа:
- шесть метрик PRODUCT_PLAN §4.5 считаются так, что каждую можно воспроизвести вручную из журнала событий бронирования (критерий фазы 2); исключения графика учитываются в загрузке; пороги сигналов не зависят от валюты; сигналы не дублируются при повторном пересчёте; на каждую метрику есть тест с рукотворным ожидаемым значением, включая «недостаточно данных»;
- проверка контракта: каждый маршрут `/api/**` описан в `openapi.yaml` и наоборот; проверка в CI;
- ESLint во фронтенде с запретом строковых литералов в JSX; проверка в CI;
- плюрализация по ICU в интерфейсе (ru/uk/cs формы), тексты для клиентов на бэкенде из каталогов сообщений по локали клиента, шрифт покрывает грузинское письмо;
- полный набор тестов зелёный, независимое ревью и приёмка пройдены.

Риск: MEDIUM (расчёты метрик — данные для решений владельца; изменение событий — схема журнала).
