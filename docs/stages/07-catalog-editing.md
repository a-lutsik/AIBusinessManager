# Этап 07 — редактирование каталога из консоли (TD-68)

Цель: владелец сам, без API и оператора, настраивает услуги, мастеров, матрицу и график и получает работающую страницу записи (цель MVP №1, `docs/PRODUCT_PLAN.md` §1, §4.1).
Критерий готовности этапа:
1. E2E: на пустом каталоге нового мастера и услугу владелец создаёт через консоль, задаёт матрицу и график, и услуга со слотами появляется на `/book/{slug}`; клиент записывается;
2. правка цены и длительности меняет новые записи и не меняет уже созданные визиты (снапшоты движка);
3. MASTER не видит элементов редактирования и не может записать через API (403), цены ему не раскрываются;
4. невалидный ввод не даёт 500: понятная ошибка с кодом на экране и на сервере;
5. регрессия зелёная: backend и фронтенд как в CI, `npm run e2e`, `npm run e2e:oidc`; скриншоты 1280 и 375 px просмотрены.

Риск: MEDIUM (деньги и график влияют на запись клиентов). Не меняем: настройки арендатора, создание пользователей Keycloak, ограничения TD-63 по валютам.

## Решения координатора
- Удаления услуг и мастеров нет: только `active=false` и `publicVisible=false`, история ссылается на них. Уже созданные визиты при деактивации остаются, экран об этом предупреждает.
- `keycloakUserId` в форме не показывается и при сохранении передаётся без изменения: привязку входа делает оператор, форма не должна её стирать.
- Цена вводится в основных единицах валюты арендатора, в API уходят минорные через ту же логику знаков, что в `formatMoney`; без округления: лишние значащие разряды, пустая и отрицательная цена — ошибка.
- Деактивированный мастер теряет доступ к консоли (403 `SPECIALIST_INACTIVE`); его визиты не переносятся, только отменяются. Снятие привязки входа — явный маршрут.
- Правки каталога пишутся в аудит (`docs/PRODUCT_PLAN.md`), без ПДн.
- Время в графике вводится как `ЧЧ:ММ` локально для арендатора, в API минуты от полуночи.
- Правило `timeFormat24h` остаётся в TD-65.
