# Этап 03 — готовность к пилоту

Цель: закрыть условия приёмки этапа 02, без которых нельзя запускать пилот с реальными данными.
Критерий готовности этапа:
- бэкапы обеих БД (приложение и Keycloak) выполняются по расписанию в прод-стеке, а скрипт restore-drill восстанавливает свежий бэкап в одноразовый экземпляр и сверяет данные; drill прогнан хотя бы раз;
- есть скрипт smoke-проверки первого деплоя (TD-21), прогнанный на локальном прод-стеке;
- CI на GitHub Actions на каждый push и PR: сборка, ArchUnit, юнит и IT на Testcontainers, typecheck и web-сборка фронтенда, проверка прод-compose; команды CI прогнаны локально;
- тест-классификатор не даёт денежному полю с «неденежным» именем дойти до мастера (TD-22);
- продуктовые решения TD-17/18/19 приняты пользователем и реализованы с тестами;
- полный набор тестов зелёный, независимое ревью и приёмка пройдены.

Риск: HIGH (данные пилота, авторизация мастера).
