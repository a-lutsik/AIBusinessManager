# Этап 02 — прод-конфигурация и права мастера

Цель: выполнить условия приёмки этапа 01 (C1–C3 = TD-12…TD-14), чтобы стек можно было развернуть для пилота.
Критерий готовности этапа:
- в профиле `prod` приложение не стартует с дефолтными паролями обеих ролей БД, без issuer-uri и без явного списка CORS-origins; демо-сид выключен;
- `docker-compose.prod.yml` поднимает БД, Keycloak (режим `start`, своя БД, админ из секретов) и приложение; снаружи хоста недоступны 5432 и 8081 (только 127.0.0.1 для reverse proxy); compose не запускается без обязательных секретов;
- прод-realm без тестовых пользователей и direct grants, redirect/origins из переменных;
- CORS-origins задаются свойством `app.cors.allowed-origins`; неразрешённый origin получает отказ;
- MASTER не получает цены, суммы и выручку ни в одном ответе `/api/app/**`, не читает чужие матрицу и график, не читает правила тенанта; проверено тестом, который обходит все GET-маршруты от имени мастера;
- полный набор тестов зелёный, независимое ревью и приёмка пройдены.

Риск: HIGH (секреты и периметр, авторизация).
