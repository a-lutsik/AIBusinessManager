# Приёмка Cadence

Дата: 2026-10-31. Основа: коммит `c542d6d` (этап 05) и незакоммиченные правки этапа 06. Приёмка архитектора по политике, п. 4.3. Объём — пилот с одним арендатором: веб-консоль и публичная запись; не весь план продукта (`docs/PRODUCT_PLAN.md`).

## Что реализовано и принято (этапы 01–06)
- Операционный срез (фазы 1A/1B плана): арендаторы с RLS, каталог услуг и мастеров с матрицей и графиком, движок записи (снапшоты, GiST-исключение, статусы), публичная запись `/book/{slug}` с `.ics` и ссылкой управления `/b/{id}?token=`, CRM из записи, роль MASTER без телефонов и денег, правила записи, светлая и тёмная темы, RU и EN, демо-сид.
- Метрики (фаза 2): шесть метрик из журнала событий, Spring Batch, «недостаточно данных» при малой выборке, пояснения на дашборде.
- AI-менеджер (фаза 3): цикл инструментов, псевдонимизация имён, телефонов и идентификаторов, черновики действий с подтверждением владельца и валидацией движка, месячный бюджет токенов, журналы, экран диалога. Провайдер по умолчанию `stub`; адаптер DeepSeek есть.
- Эксплуатация: `docker-compose.prod.yml`, профиль `prod` с проверками секретов, бэкапы с проверенным восстановлением (`scripts/restore-drill.sh`), `scripts/deploy-smoke.sh`, CI (backend, frontend, compose, docker, e2e).
- Финальное тестирование (этап 06, `docs/TEST_REPORT.md`): backend 1048 тестов, 0 failed, 0 skipped (сверено по JUnit XML); Playwright 54 сценария (E1–E7, E9, AI-1…AI-8) дважды и 8 сценариев OIDC (E8), 0 failed, на изолированном стеке `cadence-e2e` с уборкой; lint, typecheck, i18n, web export зелёные.

## Что отложено (не входит в пилот)
- Фазы 4–7 плана по их критериям: живой Telegram-бот, напоминания и реактивация (есть порт канала, Trust, пакеты и stub с ручной задачей владельцу); сигналы роста с действиями (сигналы только сохраняются из метрик); лендинг-витрина; полные каталоги ka/uk/cs (65 из 217 ключей, в OIDC скрыты, TD-66).
- Редактирование каталога из консоли: экраны услуг, мастеров, матрицы и графика только для чтения; запись есть в API (`PUT /api/app/services`, `/specialists`, `/specialists/{id}/matrix`, `/schedule`, `/exceptions`). Онбординг арендатора, первого пользователя и каталога — шаг оператора (README «First owner user», TD-68).
- Маршрут удаления данных клиента (`CrmService.anonymize` без вызова, TD-46); нативные сборки iOS/Android (в этапе 06 не собирались); измерение покрытия кода (JaCoCo нет, TD-70).

## Известные ограничения (открытый техдолг, `docs/tech-debt.md`)
- Веб: статический хост обязан переписывать `/book/*`, `/b/*`, `/clients/*`, `/specialists/*` на `[param].html`, иначе ссылка клиента даёт 404 (TD-57, HIGH); ошибка слотов, включая 429, показывается как «нет слотов» (TD-55); `/b/{id}` без slug берёт слоты у демо-арендатора — критично только при втором арендаторе (TD-64); правило 24-часового формата не действует (TD-65); шрифты и иконки грузятся с Google Fonts (TD-67); `datetime.ts` без юнит-тестов, DST и Hermes не проверены (TD-69).
- Данные и метрики: расписание не версионируется, прошлые знаменатели загрузки меняются при правке графика (TD-29); дашборд только «месяц к дате» (TD-34); лаг пересчёта 1 минута, ночной пакет 03:15, в OIDC ручного пересчёта нет (TD-35, TD-66).
- AI: маскирование имён best effort — опечатка или незнакомое имя уходят провайдеру (TD-36, TD-37); формат tool calling DeepSeek подтверждается только живой проверкой (TD-41); бюджет задаёт оператор в БД (TD-42).
- Безопасность и платформа: нет проверки audience у JWT (TD-03); владелец схемы — суперпользователь (TD-05); `Navigator` expo-router в группе консоли проверен только на web (TD-62).
- Не выполнялось: job `e2e` в GitHub Actions (только локально), живой DeepSeek, прод за TLS; `Mark completed`/`Mark no-show` в браузере не нажимаются (покрыты backend-тестами); последний круг правок UI без отдельного ревью (покрыт E2E, прочитан архитектором); скриншоты финального прогона просмотрены координатором частично (`docs/TEST_REPORT.md`, раздел 8).

## Условия запуска пилота
Выполнено: все шесть этапов приняты; полное тестирование (п. 5 политики) пройдено; техдолг записан.
Блокирует запуск с реальными клиентами (шаги пользователя и оператора, приёмкой не проверялись):
1. Деплой за TLS по README «Production deployment»; `scripts/deploy-smoke.sh --strict --check-ports` с реальным токеном — PASS; `kcadm.sh` для realm `master`; `APP_RATE_LIMIT_TRUSTED_PROXIES`.
2. Статический хост веб-консоли с правилами rewrite (TD-57) и ручная проверка `/book/<slug>` и `/b/<id>?token=` на реальном адресе.
3. Офсайт-шифрованная копия бэкапов и `.env.prod`; `scripts/restore-drill.sh` на копии, возвращённой с офсайта; повторять ежемесячно и после миграций.
4. Первый зелёный прогон CI на GitHub, включая job `e2e`; branch protection на обязательные job (без `e2e`, пока он не стабилен).
5. Онбординг арендатора: tenant и владелец (README), затем услуги, мастера, матрица и график через API владельца по процедуре в README.
6. AI: до живой проверки DeepSeek (README «Live check DeepSeek») и DPA с провайдером пилот идёт с `APP_AI_PROVIDER=stub` (экран AI — демонстрация). Реальный провайдер — только после обоих шагов.
7. Приватность: уведомление клиентам со сроками хранения, включая бэкапы (README «Backups and restore»), и договорённость с владельцем, как исполняются запросы на удаление данных до появления маршрута (TD-46).
Фаза 0 плана (валидация: интервью, кандидаты в пилот) не проводилась и остаётся шагом пользователя; приёмка её результат не проверяет.
